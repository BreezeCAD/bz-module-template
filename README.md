# Шаблон модуля BreezeCAD

Модуль добавляет [BreezeCAD](https://github.com/BreezeCAD/breezecad) новые возможности и живёт **в своём репозитории**: со своими версиями, выпусками и лицензией. Программа его в себе не несёт — пользователь ставит файл `.bzmod` через **Настройки → Модули → «Установить модуль…»**.

## Новый модуль за 5 минут
1. На GitHub: **Use this template → Create a new repository**. Имя — `bz-module-<id>` (например, `bz-module-bom`). Закрытый модуль — Private.
2. В `module.json` поменяйте:
   - `id` — короткое латиницей, уникальное (`bom`); это же имя папки модуля;
   - `name`, `description` — как увидит пользователь;
   - `library` — имя библиотеки, обычно `bz-<id>`;
   - `version` — `0.1.0`;
   - `requirements.minHostVersion` — самая старая версия BreezeCAD, где модуль работает.
3. Пишите код в `src/` (C или C++; новые файлы — в `add_library(...)` в `CMakeLists.txt`). Договор с программой — в [`sdk/bz_module.h`](sdk/bz_module.h), пример — в [`src/module.c`](src/module.c).
4. В этом README опишите свой модуль — он кладётся в пакет и показывается пользователю.

## Собрать у себя
```
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release      # модуль загружается и проходит init/shutdown
```
Пакет — `build/packages/bz-<id>-<version>-<система>-<архитектура>.bzmod`. Перетащите его в окно BreezeCAD — модуль заработает сразу. Сообщения модуля — в журнале программы.

## Выпуск
1. Поднимите `version` в `module.json` (например, `1.0.0`), закоммитьте.
2. Поставьте тег той же версии и отправьте: `git tag v1.0.0 && git push origin v1.0.0`.
3. GitHub соберёт пакеты под Windows, Linux и macOS, проверит загрузку и создаст выпуск с тремя `.bzmod`.

Сборка идёт и на каждый push в `main` (без выпуска) — чтобы ошибка была видна сразу.

## Закрытые модули
- Репозиторий — Private; лицензию выбирайте сами (для платного — без открытой лицензии).
- У GitHub минуты сборки для закрытых репозиториев ограничены, а macOS считается в несколько раз дороже. Поэтому в закрытом репозитории macOS собирается **только при выпуске** (по тегу); Windows и Linux — всегда.
- Закрытые модули не попадают на общую страницу модулей BreezeCAD — их получают напрямую.

## Совместимость
- Модуль общается с программой только через C-интерфейс `bz_module.h`, поэтому не ломается при пересборке BreezeCAD. Версия интерфейса — `BZ_MODULE_ABI_VERSION`, у модуля — `abiVersion` в `module.json`.
- Функции, добавленные в программу позже, проверяйте перед вызовом: `if (BZ_HAS(host, execute)) ...`.
- Обновить `bz_module.h`: `scripts/update-sdk.sh` (или `scripts/update-sdk.sh v0.2.6` — из выпуска). Откуда текущая копия — в `sdk/SOURCE`.
- Linux-сборка идёт в контейнере с glibc 2.28 — модуль работает там же, где BreezeCAD (в том числе на старых и отечественных дистрибутивах). macOS — Apple Silicon, 15+.

## Правила модулей BreezeCAD
- Модуль **никогда не сливается** с основой программы.
- Документы меняются только через `host->execute()` — это обычные шаги, отменяемые Ctrl+Z.
- Падение модуля программа запоминает и при следующем запуске выключает его с объяснением.
